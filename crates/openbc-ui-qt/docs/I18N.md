# Localisation (JSON message catalogs)

## How it behaves

`openbc::i18n::t("menu.session")` resolves a key in this order:

1. `messages_<lang>.json` (`messages_fr.json`, `messages_cn.json`; a regional tag also tries the base language: `pt_BR` -> `messages_pt_BR.json`, then `messages_pt.json`; `zh`/`zh_CN` also tries `messages_cn.json`)
2. `messages.json` (default language, English)
3. built-in table in `cpp/i18n/messages_defaults.h` (safety net, compiled in)
4. the key text itself

Broken JSON, empty files, deleted keys and non-string values never crash anything; they just fall through to the next layer. Keys may be flat (`"menu.session"`) or nested (`"menu": {"session": ...}`). `%1`, `%2` are `QString::arg` placeholders and can be reordered per language (`"%2 sur %1"`).

## Where the files live

`<preferences root>/resources/` where the root is `SessionHistory::rootPath()`:

* Linux: `~/.config/open-bc/resources/`
* Windows: `%USERPROFILE%\.config\open-bc\resources\` (same code path as `preferences.ini` today)

The files are embedded in the binary (`:/i18n`, see `resources/i18n/i18n.qrc`) and **deployed to that folder at startup**, so deb, rpm, AppImage, Flatpak and MSI need no packaging change. Deployment rules (`deployBundled`):

* file missing -> copied
* file still byte-identical to what we deployed earlier -> upgraded when the app ships a newer one
* file edited by the user -> never touched
* delete a file to reset it to the shipped version on next start

A new language needs no rebuild: drop `messages_<code>.json` into the folder and pick it (`Catalog::availableLanguages()`).
Flatpak note: `--filesystem=host` is already granted, but inside the sandbox `QDir::homePath()` is the sandbox home, so the folder is `~/.var/app/io.github.devopsnextgenx.open-bc/.config/open-bc/resources` there (consistent with where `preferences.ini` goes today).

## Wiring (4 small edits)

**1. Resources** - register `resources/i18n/i18n.qrc` wherever the existing `:/icons/openbc.png` qrc is compiled (CMake `qt_add_resources(...)` and the cargo/`build.rs` path, which must see the same file). Add every new `messages_<lang>.json` to the qrc.

**2. Init** - `app/main_window.h`, right after `preferences` is created:

```cpp
#include "i18n/i18n.h"
...
QSettings preferences(SessionHistory::rootPath() + "/preferences.ini", QSettings::IniFormat);
openbc::i18n::Catalog::instance().init(
    SessionHistory::rootPath(), preferences.value("general/language", "auto").toString());
```

**3. Call sites** - replace literals as you touch them (old literals keep working, migration can be gradual):

```cpp
using openbc::i18n::t;
auto* sessionMenu = window.menuBar()->addMenu(t("menu.session"));
auto* aboutAction = helpMenu->addAction(t("menu.help.about"));
tabs->addTab(home, t("tab.home"));
window.setWindowTitle(t("window.title.folder", session->title()));
```

Every key used must also be added to `messages_defaults.h` (that is the safety net), then regenerate the default file:

```bash
cpp/tools/i18n_test/build_and_run.sh --dump > resources/i18n/messages.json
cpp/tools/i18n_test/build_and_run.sh --check resources/i18n     # lists missing / unknown keys per file
```

**4. Options page (optional)** - `options/` new "Language" control: combo with `"auto"` + `availableLanguages()`; on OK write `general/language` and call `Catalog::instance().setLanguage(code)`. Menus are built once at startup, so either ask for a restart or rebuild them from an `addListener()` callback.

## Optional: also install the files next to the binary

Not required (the qrc copy is enough). If you want them on disk for packagers, add to CMake:

```cmake
install(DIRECTORY resources/i18n/ DESTINATION share/openbc/resources
        FILES_MATCHING PATTERN "messages*.json")
```

`defaultBundledDirs()` already looks in `<exe>/../share/openbc/resources` and `<exe>/resources`; the rpm `%files` entry `/usr/share/openbc/` covers it.
